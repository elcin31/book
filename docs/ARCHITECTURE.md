# BOOK 1.0: архитектурное решение

## Движок

Выбран EPUB.js 0.3.93 как зрелый механизм reflow и CFI, изолированный за `ReaderEngine`. FB2 преобразуется в локальный EPUB3; пользовательский интерфейс не знает, каким был исходный формат. Оригинал сохраняется отдельно, байт в байт.

| Критерий | EPUB.js + адаптер BOOK | Foliate-js | Собственный layout engine |
|---|---|---|---|
| EPUB3 | Reflow, spine, EPUB CFI, HTML TOC и NCX; интерактивность выключена | Широкая поддержка EPUB, собственный renderer | Потребовалась бы отдельная реализация спецификаций |
| FB2 | Контролируемый адаптер в EPUB3, главы, форматирование, растровые изображения и локальные сноски | Есть собственный FB2-модуль | Парсинг прост, надёжный layout существенно сложнее |
| Safari | Проверка в Playwright WebKit; iOS-ограничения обрабатываются в оболочке | Веб-компоненты и ESM потребовали бы отдельной проверки интеграции | Всё поведение WebKit пришлось бы сопровождать самостоятельно |
| Позиции | Независимые от размера шрифта CFI; короткий синхронный журнал плюс IndexedDB | Собственные механизмы позиций/CFI | Требуется разработать стабильные якоря и миграции |
| Навигация | Spine + вложенное TOC + проценты + поиск | Поддерживается | Нужно реализовать |
| Типографика | Переопределение через темы и повторный показ текущего CFI | Поддерживается | Риск собственных ошибок пагинации |
| Размер | Движок около 378 КБ minified / 117 КБ gzip, загружается при открытии книги | Модульная библиотека; точный размер зависит от интеграции | Неизвестен до реализации |
| Состояние | Стабильный npm-релиз старый (2023); это осознанный риск сопровождения | npm-метаданные на момент выбора: 1.0.1, обновление 2025; менее прямой путь интеграции с React | Постоянная высокая стоимость поддержки |
| Безопасность | Предварительная очистка и sandbox; небезопасный XML-парсер транзитивной зависимости заменён override на 0.9.12 | Также потребовалась бы защита недоверенного содержимого | Максимальная ответственность за каждую границу |
| Замена | Один адаптер; UI использует контракт BOOK | Может стать следующим адаптером | Возможно, но затронет больше кода |

Нет утверждения о полной поддержке EPUB3: фиксированная вёрстка отклоняется при импорте, JavaScript и мультимедиа отключены. Выбор отдаёт приоритет стабильному чтению обычных текстовых книг. Библиотека Foliate остаётся кандидатом для следующей версии, когда будут отдельные тесты совместимости и ресурсов на реальном Safari.

## Путь данных

Файл → проверка полноты чтения, размера и SHA-256 → распаковка в module worker → проверка OPF/FB2 → DOMPurify и нормализация → повторная проверка XHTML, manifest/spine и доступного содержимого → атомарная запись метаданных и двух ArrayBuffer (EPUB для чтения, исходный файл) → lazy-loaded ReaderEngine → sandboxed iframe → проверка видимого текста/декодированного изображения.

В 1.0.2 нормализованная копия имеет отдельную версию и SHA-256. При открытии повреждённая копия восстанавливается из сохранённого оригинала с проверкой исходного хеша; атомарно заменяется file record, пользовательские данные не мигрируют и не сбрасываются. Нет массового прохода по библиотеке. Сроки ожидания, `displayError` и проверка реального содержимого закрывают случаи, когда EPUB.js создал iframe или оставил Promise незавершённым, но чтение не началось. Подробности и границы проверки: [QA 1.0.2](QA-1.0.2.md).

Хранение оригиналов в ArrayBuffer выбрано после воспроизводимой ошибки Blob/File в WebKit IndexedDB. Blob создаётся только для скачивания. Сортируемые данные библиотеки отделены от тяжёлых файлов: открытие главного экрана не считывает все EPUB.

CFI сохраняется при `relocated`: сначала короткая синхронная запись в localStorage, затем Dexie. При следующем открытии выбирается более новая валидная позиция. Индекс процентов строится после первого отображения; перелистывание доступно сразу. Размер шрифта и геометрия страницы не являются координатой сохранения.

Время чтения агрегируется по локальному календарному дню каждые 15 секунд, при смене видимости и закрытии читалки. В скрытом приложении, открытой панели или после 120 секунд без действий время не учитывается. Это приблизительная локальная статистика, не телеметрия.

## Безопасность и лимиты

- Внутренние DTD и XML entities отклоняются; внешняя декларация XHTML/NCX DOCTYPE удаляется без загрузки. ZIP-пути с `..`, обратным слешем и абсолютным корнем отклоняются.
- До распаковки проверяются заявленные размеры записей. Worker прерывается через 30 секунд; лимиты защищают UI от обычных ZIP bombs.
- DOMPurify удаляет исполняемые/встраиваемые элементы и обработчики событий. CSS, внешние URL, `srcset` и MathML удаляются. Статические SVG очищаются отдельно и показываются как изображения; SVG с единственным растровым image упрощается до `img`. Данные SVG допускаются только для URI, созданного текущей санитизацией. Скрипты, foreignObject, анимация и внешние SVG-ссылки запрещены.
- Iframe имеет `sandbox="allow-same-origin allow-scripts"` без `allow-popups`. WebKit требует разрешения `allow-scripts` даже для DOM-обработчиков доверенного родительского окна. Это разрешение не используется как защита от кода книги: **каждая нормализованная глава получает `script-src 'none'`**, а DOMPurify заранее удаляет скрипты и обработчики. CSP запрещает код книги, сохраняя работу родительских обработчиков касаний и выделения. Основной документ получает CSP и прочие заголовки от Vercel.
- Исходный файл сохраняется, но не исполняется. Восстановление копии повторно прогоняет оригинал через импорт, не доверяя сохранённому HTML.
- `npm audit --omit=dev` проверяется перед публикацией. Override `@xmldom/xmldom` закреплён; при обновлении движка его нужно пересмотреть.
- Квоты хранения проверяет браузер; `persist()` является запросом, а не гарантией. Ошибки записи прогресса видны пользователю.

Санитизация выполняется в главном потоке, поскольку DOMPurify требует DOM; распаковка выполняется в worker. Импорт последовательный, без одновременной распаковки нескольких книг. Поиск ограничен первыми 200 совпадениями, отменяем и уступает UI между главами. EPUB.js и его iframe layout не гарантируют 120 FPS на аппаратном iPhone — это требует профилирования на устройстве.

## Развитие

Для BOOK 2+ можно добавить адаптер Foliate, миграции Dexie, полнотекстовый индекс в worker и опциональную синхронизацию. Добавление backend не должно менять контракт движка и локальную модель чтения. Секретов, аккаунтов, платежей и привязки к чужой инфраструктуре в 1.0 нет.

# BOOK 1.0.2 — открытие импортированных книг

Дата: 26 октября 2026 года. Репозиторий: `elcin31/book`. Production: <https://book-five-smoky.vercel.app>. Используется существующий Vercel `book`, `prj_ZO29qu33KuxoiaPto5pU1Hfi3PSV`.

## Установленные причины

Конкретный пользовательский файл не был приложен. Его открытие после исправления не подтверждено. Ниже — воспроизведённые дефекты существующего кода и результаты на независимых файлах.

1. **Нормализация удаляла содержимое.** `sanitizeChapter` удалял inline SVG целиком, включая распространённую обёртку `<svg><image xlink:href="…"/></svg>`. Все `.svg` удалялись из архива. В первом случае первая страница становилась пустой; во втором spine мог ссылаться на отсутствующий SVG. Распакованный ZIP считался достаточным основанием для успешного импорта. Браузерный тест на настоящей сборке 1.0.1 воспроизводит пустую обложку и затем проверяет её восстановление из оригинала в 1.0.2.
2. **EPUB.js мог не завершить ошибочное открытие.** В EPUB.js 0.3.93 ошибка загрузки раздела посылается событием `displayError`, при этом Promise `display()` может остаться pending. Движок ожидал Promise без отдельного обработчика этого события и без срока ожидания. Регрессионный тест воспроизводит именно эту комбинацию.
3. **Созданный iframe не доказывал успешное чтение.** Не проверялись ненулевые размеры, реально видимые текстовые прямоугольники и декодирование изображений. Намеренно пустое XHTML давало нулевую ширину iframe; такая страница теперь сохраняется в последовательности, получает временный пробельный маркер только в live DOM и явные кнопки перехода. Её маркер не записывается в книгу или прогресс.

Нормализатор, `archive.ts` и `db.ts` не менялись между рабочей 1.0 (`a9ff885`) и 1.0.1 (`8a70188`): удаление SVG существовало **до fullscreen-обновления**. Ошибка event/Promise также присутствовала раньше. Новая геометрия сохранена; полный откат 1.0.1 не выполнялся. Дублирование `xmlns` было воспроизведено в jsdom, но не на проверенном простом XHTML в браузерах; оно не объявляется доказанной причиной пользовательского сбоя. Выходной XHTML теперь повторно разбирается как XML.

## Аудит цепочки и изменения

| Этап | Проверка и итог |
|---|---|
| Files → File API | `arrayBuffer()` ограничен 30 секундами; размер результата сравнивается с `File.size`. Неполный iCloud-файл не сохраняется как успешно импортированный. Сам системный диалог и iCloud на устройстве не проверены. |
| Декодирование | XML-декларация и BOM UTF-16 учитываются, недопустимая кодировка отклоняется. UTF-8/Windows-1251 FB2 и TXT проверяются отдельными файлами. NCX приводится к UTF-8 перед EPUB.js. |
| Нормализация EPUB | Сохраняются порядок spine, ID и структура глав. Префиксный XHTML приводится к каноническим элементам. SVG с единственным растровым изображением становится `img`; векторная обложка — очищенным изображением. Отдельные SVG/raster spine-страницы получают XHTML-обёртку на том же индексе. Локальные ссылки HTML/NCX перенаправляются к обёртке; пути с пробелами и percent encoding проверены. |
| Безопасность | Скрипты, обработчики, foreignObject, активные SVG и внешние ресурсы запрещены. Издательские CSS по-прежнему заменяются управляемой типографикой. CSP каждой главы содержит `script-src 'none'`. Разрешение sandbox для родительских WebKit-обработчиков не разрешает код книги. |
| Проверка результата | До записи проверяются container/OPF, уникальные manifest ID, все itemref и файлы spine, корректный XHTML body, безопасность глав, объявленное оглавление. Требуется хотя бы один текстовый раздел или доступное поддерживаемое изображение. Пустой или повреждённый EPUB не попадает в библиотеку. |
| IndexedDB | Оригинал и нормализованные байты остаются ArrayBuffer. Добавлены необязательные версия нормализатора, SHA-256 нормализованной копии и результат проверки. Схема Dexie v1 и название БД сохранены. `db.ts` и `archive.ts` не изменены. |
| Восстановление | При открытии проверяются сохранённые данные; повреждённая/небезопасная копия или старая пустая первая страница восстанавливается из оригинала. Проверяется исходный SHA-256. Один file record заменяется атомарно. ID, пользовательское название, коллекции, избранное, CFI, журнал позиции и аннотации не перезаписываются. Неудача оставляет запись на месте. Массовой миграции нет. Повторный импорт того же SHA исправляет копию без дубликата книги. |
| EPUB.js | Ожидание ненулевого mount через ResizeObserver; `book.open(binary)`, `book.ready`, CFI и display имеют отдельные сроки ожидания. Общий предел движка — 90 сек.; открытие ZIP — 60, ready/display — 30, проверка CFI — 10. Подписка на `displayError` завершает ошибку немедленно. Отменённое открытие уничтожается. CFI проверяется до создания rendition, чтобы не уничтожить ещё запускающийся renderer. Для проверенной страницы-изображения EPUB.js CFI без текстового узла восстанавливает тот же spine-раздел, сохраняя исходный локатор; текстовые позиции по-прежнему проверяются как Range. |
| iframe → видимое содержимое | После display и двух кадров проверяются размеры, документ/body, вычисленная видимость, текстовые Range в пределах страницы и `naturalWidth/naturalHeight` изображения. Сначала проверяются видимые точки страницы, чтобы не обходить предыдущие страницы длинной главы при каждом перелистывании. Есть повторная проверка после reflow и возвращения видимости приложения. |
| Reader | «Подготавливаем книгу…», ошибка формата, ошибка отображения, отдельная ошибка CFI, повторное открытие и восстановление из оригинала. Пустая страница даёт переход дальше или к тексту. Статус расположен вне mount и виден даже при нулевой области книги. Успешный CFI не заменяется ошибочной начальной позицией. |
| PWA | Хешированные entry/Reader/engine chunks и precache обновляются одной сборкой. Проверка обновления при возвращении и раз в минуту онлайн. Активация/перезагрузка откладывается до выхода из чтения и завершения импорта. Быстрое нажатие обновления ожидает состояния waiting; controllerchange учитывается независимо от эвристики Workbox. Очистки IndexedDB или всех Cache Storage нет. |

Диагностика хранит до 60 локальных событий и показывает последние 20: версии, коды стадий, размеры, количество разделов и признак восстановления. Не сохраняются текст, названия, URL ресурсов, CFI или выделения. Ничего не отправляется на сервер.

Основные изменённые модули: `src/engine/importer.ts`, `bookDocument.ts`, `inspection.ts`, `EpubEngine.ts`, `ReaderEngine.ts`, `readerHealth.ts`, `readerFailure.ts`; `src/lib/bookRecovery.ts`, `readerDiagnostics.ts`, `version.ts`; `src/components/Reader.tsx`, `Settings.tsx`; `src/App.tsx`, `src/styles.css`, `src/types.ts`, `package.json`/lock; регрессионные тесты и документация. Библиотека и хранилище пользовательских настроек не переписаны.

## Проверенные книги

Новые файлы генерируются в `tests/support/books.ts` независимо от `public/books` и не содержат сторонних защищённых текстов:

- EPUB2 с NCX; EPUB3 с HTML nav; русский текст, вложенные главы и локальное растровое изображение.
- Префиксный XHTML; пути OPF и главы с пробелами/percent encoding.
- Inline SVG с raster image; векторная SVG-обложка; SVG как отдельный spine-раздел в EPUB2 и EPUB3. У EPUB2 проверяется возврат на обложку через NCX.
- Издательский CSS с белым текстом; титульная и намеренно пустая первая страница.
- FB2 UTF-8, FB2 Windows-1251, FB2.ZIP с файлом во вложенном каталоге.
- TXT UTF-8 и TXT Windows-1251.
- EPUB без доступного содержимого; отсутствующая глава; некорректный ZIP.
- EPUB с настоящим несжимаемым PNG 2048 × 2048 и 300 текстовыми абзацами; исходный файл около 12,1 МиБ.

Для успешных текстовых файлов проверяются **видимые ненулевые текстовые прямоугольники**, не только iframe или `textContent`. Для обложки проверяется декодированное видимое изображение, повторное открытие на этой же странице с прежним CFI, затем переход к тексту. Каждый формат сохраняется в IndexedDB, перелистывается и открывается после перезагрузки страницы. Сохранены исходные сценарии стартовых книг, поиска, заметок, резервных копий и защиты от кода EPUB.

## Проверки релиза

TypeScript strict / production build — успешно. Vitest — **41/41**. Полный Playwright — **84/84** в Chromium и WebKit, 15,5 минуты, включая оба реальных Workbox upgrade-теста. Prettier и `git diff --check` пройдены. `npm audit --omit=dev` — **0 известных уязвимостей**. Проверялась production-сборка Vite, не dev renderer.

Сохранены проверки размеров 320/375/390/402/430/1440 CSS px; чтение EPUB/FB2 на 375/390/402 × 874, повороты, шрифты 14/36 px, пагинация и свиток. Измеряются границы строк и видимость прежнего текстового якоря после reflow; показ панелей не меняет iframe или CFI. При 402 × 874 без системных отступов область книги остаётся 370 × 836 px, верх — 12 px. Standalone-флаги и safe area проверены имитацией.

Отдельные fault-injection сценарии: неверный CFI без перезаписи позиции и необработанных исключений, нулевой mount и скрытый iframe с явной ошибкой и успешным повтором, повреждённая нормализованная копия с lazy repair, повреждённый оригинал с безопасным отказом. Проверены сохранность ID, названия, избранного, коллекций, закладок/заметок, оригинальных байтов и CFI; дедупликация не мешает восстановлению.

Большой EPUB: **12 701 665 байт (12,1 МиБ)**, PNG 2048 × 2048, 300 абзацев:

| Измерение | Chromium | WebKit |
|---|---:|---:|
| Импорт, включая File API теста | 9,149 с | 3,411 с |
| Открытие после импорта | 3,586 с | 3,035 с |

CDP-память выбиралась каждые 200 мс в Chromium, включает работу тестового `setInputFiles` и не охватывает worker, native/WebKit и GPU allocations. Отдельные максимумы не являются суммарной пиковой памятью процесса или iPhone. Время зависит от облачной машины. Превышение лимитов ZIP проверяется отдельными тестами до распаковки.

Команды: `npm test`, `npm run check`, `npm run build`, `npm run format:check`, `npm audit --omit=dev`; полный браузерный прогон — `BOOK_LEGACY_DIST=... npm run test:e2e`. В этой Linux-среде использовался локальный wrapper зависимостей WebKit через `BOOK_WEBKIT_EXECUTABLE`; обычная установка Playwright требует `npx playwright install --with-deps chromium webkit`.

## Воспроизведение PWA-upgrade теста

В игнорируемую папку `.qa-libs/legacy-101` извлекается **только** дерево `elcin31/book` из коммита `8a7018890168318fb1d16e31b37435a163c40299`; устанавливаются зависимости и строится 1.0.1. После сборки текущей версии:

```sh
BOOK_LEGACY_DIST="$PWD/.qa-libs/legacy-101/dist" npx playwright test tests/e2e/upgrade.spec.ts
```

Тестовый localhost-сервер последовательно отдаёт обе сборки с одного origin. В 1.0.1 импортируется независимая книга со SVG-обложкой, воспроизводится пустая обложка, сохраняются позиция, закладка и 27 px. После обычного «Обновить» проверяются версии shell/Reader 1.0.2, lazy repair, все сохранённые данные и холодный офлайн-запуск. Следующий тестовый worker ожидает выхода из книги и явного обновления. Сервер существует только внутри теста; в приложение backend не добавляется. Без переменной upgrade-тест пропускается явно.

## Непроверенные сценарии и ограничения

- **Точный пользовательский файл отсутствует; его исправление не подтверждено.**
- Физический iPhone 17, iOS Safari и установленная iOS PWA не были доступны. Playwright WebKit на Linux — проверка движка браузера, а не устройства.
- Не проверены нативный Files picker, загрузка оригинала из iCloud Drive, фактические safe area/Dynamic Island, системная клавиатура и выделение, установка/перезапуск с домашнего экрана, реальное сворачивание/возобновление iOS и выгрузка процесса при нехватке памяти. Standalone-флаги и safe area в автоматических тестах имитируются.
- Измерения времени/JS-памяти относятся к облачному Linux; полная пиковая память iPhone, native allocations и 120 FPS не измерялись. Тест не является нагрузочной гарантией для любого файла до предельных 50 МБ.
- По-прежнему явно отклоняются DRM и fixed-layout EPUB; интерактивные SVG/JavaScript, PDF и MathML не поддерживаются.

Для установленной версии: открыть библиотеку онлайн и применить предложенное «Обновить», затем проверить собственный файл офлайн. Оригиналы, закладки и настройки при этом остаются на устройстве; удаление PWA или очистка данных не требуются.
